# プロファイル：article（Web 記事・技術ブログ。`source_format: html`）

| 項目 | 決まり |
|---|---|
| 入力の形 | 見出し（`#`〜）と段落、リスト、表、コードブロック。画像は絶対 URL のリンク |
| セクションの取り方 | 本文の見出し（`scaffold.py` が `sections.headings` と `toc_for_*` で返す）。**本文の先頭の `# 題名`（記事の題）はセクションにせず、その次のレベル（多くは `##`）の並び**を使う（`scaffold.py` の返したとおりでよい）。**12 を超える**ときは、上位の見出しでまとめる。見出しが無い短い入力は**分割なし**（目次の節ごと省く） |
| 目次の書き方 | `- N : [見出し](#アンカー)`（README では `[見出し](./01_source.md#アンカー)`）。アンカーは `scaffold.py` が返したものを使う |
| 本文の扱い | **複製して変えない**。ナビ・広告・関連記事の残りがあっても消さず、README の「概要」の末尾に注意として書く |
| 根拠の示し方 | `「<見出し名>」の節「…」`（見出し名＋引用）。見出し名は `決まり1：…` のように記号を含んでいても**見出しの文字をそのまま**書く（C-7 が名前で照合する）。引用は入れ子の「」を含まない部分を切り出す |
| 02 の `<範囲>` | 見出しの節なので `（見出しの節）` と書く（`references/output-formats.md` の 3） |
| 図・表・コード | コードは**そのまま引用**する（書き換えない。誤りに見える所は `【補足】` で指摘する）。引用する場所は、グループ別の解説（`out/05`）の詳細でよい。コードブロックの中の `## …` の行は見出しとして扱われない（閉じ忘れに注意）。画像は URL のままで、内容は根拠にしない |
| 気を付ける点 | 筆者の意見と事実の区別。公開日（古い記事かどうか）。`has_figures` が `true` でも、画像の中身は読めていない。**記事の中の食い違い**（本文と表の数字が合わない、など）は、直さず・断定せず、該当する解説の中で `【推測】` を付けて指摘する（例：「前半15分」の記述と表の時間が合わない点は、どちらが正しいか本文からは決められない【推測】） |
