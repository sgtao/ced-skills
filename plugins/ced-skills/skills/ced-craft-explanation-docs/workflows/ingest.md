# 取り込み（ingest）

入力の Markdown から作業フォルダの骨格を作り、**01_source.md の冒頭**（要約・セクション目次）と README の骨格を埋めるまで。
`<RUN>` と `<SKILL_DIR>` は SKILL.md の定義。オプションは `--help` が正。

```bash
<RUN> <SKILL_DIR>/scripts/scaffold.py --help
```

## 手順

1. **作る**: 入力のパスを渡す。場所・名前の指定があれば `--dest`。
   ```bash
   <RUN> <SKILL_DIR>/scripts/scaffold.py <入力.md> [--dest <フォルダ>]
   ```
   標準出力の JSON を読む（`dest`・`profile`・`title`・`frontmatter_warnings`・`summary_draft`・`sections`）。
   `DEST_EXISTS` で止まったら、続きから行うか・別の名前にするか・やめるかをユーザーに聞く（既定を置かない）。
   フォルダを渡されたとき（`mode: existing_folder`）は何も書かれない。足りない冒頭だけを足す。
2. **プロファイルを読む**: JSON の `profile` に当たる `references/profiles/<名前>.md` の 1 ファイルだけを読む。
   frontmatter が無かった（`frontmatter_warnings`）ときは、`profile_reason` が妥当か本文で確かめる。違うと考えても**ユーザーには聞かず**（質問は Step 0 の 1 回だけ）、本文に合うプロファイルの文書を読んで進め、判断した理由を `out/00_run-report.md` に 1 行書く。
   入力の決まり（frontmatter の項目・止まるとき）は `references/input-contract.md`。
3. **セクションを決める**: プロファイルの「セクションの取り方」に従う。
   - `sections.toc_for_source`・`toc_for_readme` に行があれば、そのまま使う（動画のチャプター・記事の見出し）。12 を超えるときは上位の見出しでまとめる。
   - 行が無く、見出しも無い**短い入力は分割なし**。動画でチャプターが無いときは、字幕を読んで**スキルが区切る**（順序は変えない）。
   - **本文には何も挿入しない**。セクションは目次の中だけにある。
4. **01_source.md の冒頭を埋める**（Edit で 2 か所）。
   - `{{summary}}` → 要約（**200 字以内**）。`summary_draft` は下書き。本文を読んで確かめて、自分の言葉で書く。下書きが要約になっていない（著者名・所属だけの行、題名と同じ文など）ときは、**捨てて**本文から書く（警告は不要）。
   - `{{toc_block}}` → 目次があるときは、次の 5 行以上のブロックに置き換える（`{{toc_block}}` の文字は残さない）。分割なしのときは**空にする**（文字ごと消す）。
     ```
     -----
     [toTop](#totoppage)
     ## セクション目次
     - 1 : …（toc_for_source の行を、そのまま全部）

     ```
     ひな形では `{{toc_block}}` と `-----` が**同じ行**に続いている（`{{toc_block}}-----`）。Edit では `{{toc_block}}` の文字だけを置き換え、置き換えたあとに `-----` が**独立した行**になるよう、ブロックの末尾に空行を 1 つ含める（`-----` を二重に書かない）。分割なしのときは `{{toc_block}}` の文字だけを消す（`-----` は残す）。
     最後の空行まで含めて置き換える。置き換えたあとのファイルは、要約の行、空行、このブロック、`-----`、`[toTop](#totoppage)`、空行、`<!-- source-body:start -->` の順になる（`{{toc_block}}` の直後に、ひな形の `-----` が続いている）。
5. **README.md の骨格を埋める**（Edit）。
   - `{{sections}}` → 目次があるとき、1 行の説明（「動画の概要欄のチャプターによる区切りです。」「入力の見出しによる区切りです。」「スキルが区切ったセクションです。」のどれか）、空行、`toc_for_readme` の行。分割なしのときは `分割なし` の 1 行だけ。**01_source.md の目次と同じ内容**にする。
   - `{{overview}}` → 本文の概要（**200〜400 字**。上限 400 字。数え方は記号・空白を除く。`references/output-formats.md` の 5-1）。図が再現されていない入力（`conversion` が `direct`・`model-read`、または「再現できなかったもの」の節がある）では、その注意を末尾に書く。図が再現されている入力（SVG・表がある）では、注意は要らない（書いてもよい）。ナビ・広告の残りがあれば、それも書く。
   - `{{content_type}}` → Step 0 で決めた内容の種類を、**この 3 つのどれか 1 つ**そのまま書く: `学習・ビジネス`／`技術・ハウツー`／`考察・読み物`（括弧・説明は付けない。`references/content-types.md`）。
   - `{{summary_block}}`（生成AIの総括）は**ここでは触らない**（転記のときに埋まる）。
6. **確かめる**（取り込みの完了条件）:
   ```bash
   <RUN> <SKILL_DIR>/scripts/check_docs.py <作業フォルダ> --only C-5,C-9,C-10,C-11
   ```
   4 項目が `PASS` ならよい。`C-9` が落ちたら、本文を変えてしまっている（元の入力から作り直す）。
   このとき C-1・C-2・C-4 はまだ不合格でよい（02・11・12 が無く、`{{summary_block}}` が残る）。

## してはいけないこと

- 入力の Markdown を書き換えない。
- `01_source.md` の `<!-- source-body:start -->` より後ろを書き換えない（整形・清書・見出しの挿入もしない）。
- `scaffold.py` を書き換えない。失敗は `REASON=` の行と標準エラーをそのまま報告する。
