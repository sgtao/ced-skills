# 自己評価と完了報告（review）

転記のあと、**検査（機械）と読み合わせ（LLM）**を合格するまで繰り返し、完了報告を返す。上限は **3 回**。
`<RUN>` と `<SKILL_DIR>` は SKILL.md の定義。観点の詳細は `references/self-review.md`。

## 手順

1. **機械の検査**（C-1〜C-12）:
   ```bash
   <RUN> <SKILL_DIR>/scripts/check_docs.py <作業フォルダ>
   ```
   out/ を `.work/out/` へ移してあるときは、`--out-dir <作業フォルダ>/.work/out` を付ける。
   機械で読みたいときは `--json`。出力の `FAIL` の項目と場所（ファイル・行）を読む。
2. **読み合わせ**（R-1〜R-4）: `references/self-review.md` の観点で、`01_source.md` と突き合わせる。見つけた問題は、場所と直し方を 1 行ずつ書き出す。
3. **直す**: 不合格の項目と、読み合わせで見つけた問題を、**元の `out/` のファイルで直す**（最終ファイルを直接直さない。二重管理を避ける）。直したら `assemble.py` をやり直し（`workflows/assemble.md`）、1 に戻る。
   - 字数の超過は、**文章を直す**。上限・数え方・検査の側を変えない。
   - C-8（引用の不一致）は、引用を本文に合わせて直す。本文に無い文だったときは、引用をやめて `【補足】` にするか、削る。
4. **回数**: 1〜3 を 1 回として、**3 回まで**。機械の検査が 1 回目で全項目 `PASS` でも、読み合わせで直したときは、直して `assemble.py` をやり直したあとの往復を **2 回目**と数える（完了報告の `<n> 回目` は、最後に合格した往復の番号）。読み合わせで直さなかったときは 1 回目。3 回目でも不合格が残るときは、直さずに残りを完了報告に書いて終える。
5. **記録**: 回ごとの結果（項目・合否・直した内容）を `out/00_run-report.md` の「自己評価」に書き足す。
6. **完了報告**を返す（下記）。

「合格」と書けるのは、`check_docs.py` の出力（全項目 `PASS`）を示せるときだけ。実行できなかった（コードが実行できない環境）ときは、「機械での検査は未実施」と書く。

## 完了報告の形

```
解説メモを作りました。
- 作業フォルダ: <パス>（絶対パス）
- 入力: <入力のパス>（絶対パス。プロファイル: <video|article|document>／内容の種類: <…>）
- 作ったファイル: README.md・01_source.md・02_explanation_memo.md・11_question_and_answer.md・12_LLM_prompts_as_guide.md
- 検査: C-1〜C-12 合格（<n> 回目）／読み合わせ R-1〜R-4 合格
- 採った既定値: <聞かずに決めたこと>
- 確認していないこと: <あれば>
- 残った項目: <あれば。なければ「なし」>
- 次にできること: スライドにする（指示文の例）
```

- 不合格が残ったときは、1 行目を「解説メモを作りましたが、検査に通っていない項目があります。」にして、項目と場所を並べる。
- 「検査」の行には `check_docs.py` の結果（`結果: 11 PASS / 0 FAIL`）をそのまま引用する。
- 「確認していないこと」には、たとえば「図に基づく記述（図が再現されていない入力）」「`【推測】` の当否（字幕の聞き取り違いの推測）」を書く。

### 次にできること（スライドにする指示文の例）

このスキルは `ced-websearch-slide-ja` を呼ばない。次の指示文を、そのまま貼れる形で案内する。

```
<作業フォルダ> の README.md・02_explanation_memo.md・11_question_and_answer.md に基づき、解説スライドを作ってください。

- 本文に無い情報を足すときは、足したことと出典を明記
```
