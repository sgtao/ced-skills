# 使い方を聞かれたとき（help）

「このスキルの使い方を教えて」「どう頼めばいい？」「何ができる？」と聞かれたら、**何も作らず、スクリプトも実行せず**、下の内容を日本語で答える。長いときは、聞かれた部分だけを答える。
質問は増やさない（聞き返さず、まず答える）。

## 答える内容

### 何をするスキルか
`ced-url-to-md` が作った Markdown（YouTube の字幕・Web 記事・PDF／Office 資料）を **1 つ**渡すと、入力の種類によらず同じ形の解説メモ一式を作る。

| 作るもの（作業フォルダ） | 中身 |
|---|---|
| `README.md` | 入口。概要・セクション・総括・各ファイルへのリンク |
| `01_source.md` | 入力の複製（本文は一字も変えない）。冒頭に要約とセクション目次 |
| `02_explanation_memo.md` | 解説メモ（体系的解説・深掘りの質問への回答・グループ別の解説・活用案） |
| `11_question_and_answer.md` | FAQ（根拠の引用つき） |
| `12_LLM_prompts_as_guide.md` | 生成 AI にこの内容をガイドさせるシステムプロンプトと質問例 |

途中の生成物は `out/` に残る。

### 頼み方の例
- 「`<入力>.md` から解説メモを作って」（基本）
- 「`<入力>.md` から解説メモを作って。不明点は最初に質問して、その後一気通貫で」
- 「質問なしで一気通貫で作って」（既定で進める。採った既定は `out/00_run-report.md` に残る）
- 「`<作業フォルダ>` の FAQ だけ作り直して」「Phase 4 だけ」「続きから」（部分実行・再実行）
- 「`<作業フォルダ>` を検査だけして」「転記だけやり直して」

### 入力の用意
- URL・PDF・Office 資料は、先に `ced-url-to-md` で Markdown にする（このスキルは URL を取得しない）。
- 入力は 1 つずつ。2 つ以上は 1 つずつ頼む。

### 質問
最初に 1 回だけ。入力と指示から分かる項目は聞かない（最大 4 つ、選択式）。聞くのは、作業フォルダの場所・読み手と目的・内容の種類・グループ分け・補足を足すか、の 5 つのうち分からないもの。同じ名前の作業フォルダがあるときだけ、続きから・別名・やめるを聞く。

### 入力の種類ごとの違い
| 入力 | 違い |
|---|---|
| 動画（`youtube`） | 概要欄のチャプターをセクションにする（無ければ区切りを付ける）。字幕の誤変換らしい箇所は `【推測】` を付けて扱い、書き換えない |
| 記事（`html`） | 見出しをセクションにする。コードはそのまま引用する |
| 資料（`pdf`・`docx`・`pptx`・`xlsx`） | 章・ページ・スライドをセクションにする。図が再現されていない入力では、図に基づく記述を避ける |

### 守ること（出力）
- 本文に無いことは、補足は `【補足】`・推測は `【推測】` の印を付ける。
- 最後に検査（`check_docs.py`）の結果が出る。「合格」と書くのは検査の出力を示せるときだけ。
- 解説スライドにしたいときは、完了報告の指示文を `ced-websearch-slide-ja` に貼る（このスキルは呼ばない）。

### 対象外
Markdown への変換だけ（`ced-url-to-md`）・スライドだけ（`ced-websearch-slide-ja`）・講座フォルダ専用の別スキル（`globis-course-deepdive`）の対象。

## してはいけないこと
- 使い方を聞かれただけのときに、作業フォルダを作らない・スクリプトを動かさない。
- 実装にないオプションを案内しない（オプションは各スクリプトの `--help` が正）。
