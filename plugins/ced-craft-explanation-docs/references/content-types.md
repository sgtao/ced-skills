# 内容の種類（語り口と到達点）

プロファイル（入力の形）とは別の軸。**資料の中身**で決め、解説の全体（役割・ユースケースの節・システムプロンプトの到達点）に効かせる。
判定は Step 0 で行い、結果を `out/00_run-report.md` と README の `content_type` に書く。自信が無いときだけ事前質問に入れる。

| 種類（`content_type` の値） | 当てはまる資料 | 役割（Actor） | 「ユースケース」の節の中身 | 到達点 |
|---|---|---|---|---|
| `学習・ビジネス` | 講義・解説・経営やマネジメント・業務知識・提案資料 | 専門教育者兼リサーチャー | 実務での使いどころ（いつ・どこで・だれが・なぜ・どうやって・目標） | 明日から使える行動 |
| `技術・ハウツー` | プログラミング・ツールの使い方・手順書・設定の解説 | シニアエンジニア兼技術教育者 | 手順を再現する場面・前提の環境・つまずく所 | 手順の再現と応用 |
| `考察・読み物` | エッセイ・批評・ニュース解説・対談・物語 | 編集者兼批評家 | 自分の文脈に引き寄せて考える場面 | 理解を深め、自分の意見を持つ |

## 判定のしかた

1. 題名・要約・見出しから、上の表の「当てはまる資料」に最も近いものを選ぶ。
2. 2 つに分かれるときは、**読み手が資料を読んだあとにすること**で決める（行動する → 学習・ビジネス／手を動かして再現する → 技術・ハウツー／考える・語る → 考察・読み物）。
3. 決めた理由を 1 行で `out/00_run-report.md` に書く。迷ったら `学習・ビジネス`（事前質問を許されているときだけ、聞く）。

## 種類が効く場所

| ステップ | 効き方 |
|---|---|
| Step 1 体系的解説 | 役割（Actor）を表の「役割」にする。`### 4. ユースケース` の中身を表のとおりにする |
| Step 4 グループ別解説 | 「詳細解説」の適用方法を、種類のユースケースの形にそろえる |
| Step 8-A・8-B システムプロンプト | Mission（到達点）を表の「到達点」にする。ガイド役の名前も種類に合わせる |
| Step 9 質問例 | 初心者・中級者・上級者の質問を、種類の到達点に向けて作る |

## 語り口の決まり（種類によらず）

- 日本語で書く。用語は本文の表現に合わせる（言い換えたら初出で元の語を添える）。
- 事実（本文に書いてあること）と補足（例え・一般知識・筆者の整理）を混ぜない。補足には `【補足】`、推測には `【推測】` を付ける。
- 本文に書かれていないことは「本文には書かれていない」と書く。埋めない。
