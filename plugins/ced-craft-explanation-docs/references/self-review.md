# 自己評価の観点（検査項目と読み合わせ）

`workflows/review.md` から読む。検査項目の定義は `references/output-formats.md` の「6. 検査項目」。ここでは、**落ちたときの直し方**と、**読み合わせ（R-1〜R-4）の観点**をまとめる。

## 機械の検査（`check_docs.py`）：落ちたときの直し方

| 項目 | 落ちる理由の例 | 直し方（直すのは `out/` の元のファイル） |
|---|---|---|
| C-1 必須ファイル | 5 本か manifest が無い | `scaffold.py`（取り込み）か `assemble.py` をやり直す |
| C-2 見出し | `##`・`###` の名前・順序・個数が違う | 元の `out/` の見出しを、`output-formats.md` の書式に合わせる |
| C-3 `out/` への参照 | 解説の本文に「out/…を参照」と書いた | その文を消す（最終ファイルだけで読めるようにする） |
| C-4 プレースホルダ | `{{…}}`・`TODO` が残る。取り込みの `{{summary}}` などの埋め忘れ | 埋める。残すべき文字なら言い換える |
| C-5 相対リンク | リンク先のファイル・見出しが無い | 目次のアンカーを `scaffold.py` の値に直す |
| C-6 文字数 | 要約 400・ポイントまとめ 70・活用案 400・システムプロンプト 2000・概要 400 を超えた | 文章を短くする（上限を変えない） |
| C-7 セクションの網羅 | あるセクションが 02 の「セクション別の解説」か、11 の「該当箇所」に出てこない | 足りない所に、そのセクションの根拠を書く |
| C-8 引用の照合 | 引用が本文と一字一句同じでない | 本文からコピーして貼り直す。段落をまたぐ引用は分ける |
| C-9 入力の保全 | `01_source.md` の本文を変えた | 元の入力から `scaffold.py` で作り直す（本文を手で直さない） |
| C-10 項目の一致 | 題名・URL・目次・グループ名が食い違う | 食い違いの元を直す（`out/04` のグループ名は `out/05`・`out/08` と同じ） |
| C-11 相互リンクと要約 | `01_source.md` の README へのリンク・要約が無い。README の「## 本文」にリンクが無い | 取り込みの冒頭を直す |
| C-12 総括の視点 | 横断分析が 1 行に詰められている、子箇条書きが 3〜4 個でない、一言まとめが無い | `out/06_summary.md` を、視点ごとの子箇条書きに書き直して転記し直す |

## 読み合わせ（LLM）

機械で確かめられない項目を、`01_source.md` の本文と突き合わせて確かめる。**問題を 1 件も見つけなかったときも、確かめた範囲を一言で書く**（「R-1：02 の全セクションの根拠を本文と照合した」など）。

| # | 項目 | 見ること | 合格 |
|---|---|---|---|
| R-1 | 本文との食い違い | 02・11・12 の、数字・固有名詞・因果・結論が、本文と合っているか。引用が文脈を変えていないか。本文に書かれていないことを事実として書いていないか | 食い違い 0 |
| R-2 | 補足の印 | 本文に無い記述（例え・一般知識・筆者の整理）に `【補足】`、推測に `【推測】` が付いているか。字幕の聞き取り違いを直して引用していないか | 付け忘れ 0 |
| R-3 | 内容の質 | ユースケースに、いつ・だれが・何を・なぜ・どうやって・目標があるか（内容の種類に応じた形）。具体例が 1 つ以上あるか。前のステップの繰り返しになっていないか。グループ名が内容を表しているか | 満たす |
| R-4 | 範囲の外の変更 | 作業フォルダの外・入力の Markdown を変えていないか。Git があれば `git status`。無ければ、入力の SHA-256 が `out/00_manifest.json` の `input.sha256` と同じか確かめる | 変更なし |

### 読み合わせのコツ

- R-1: 各セクションの「根拠」の引用を 1 つずつ本文で探し、その前後の文を読んで、解説が合っているかを見る（機械が照合するのは「引用が本文にあること」だけ）。
- 動画（字幕）は、数字・固有名詞・専門用語を重点的に疑う。聞き取り違いの訂正は `【推測】`。
- 資料（`conversion` が `direct`・`model-read`）は、図に基づく記述が無いか。あれば削るか、図が再現されていない旨を書く。
- 記事は、コードが書き換わっていないか（コードブロックを本文と見比べる）。

## 修正の進め方

1. 不合格の項目と、読み合わせの問題を、場所つきで書き出す。
2. `out/` の元のファイルを直す（最終ファイルを直接直さない）。
3. `assemble.py` をやり直し、`check_docs.py` を再実行する。
4. 3 回まで。残ったものは、完了報告の「残った項目」に項目と場所を書く。

**検査を通すために、字数の表記・期待値・検査の側を書き換えない。**
