# 出力フォーマット（out/ と最終ファイルの形・文字数・検査項目）

作業フォルダに何を、どの形で作るか。**正は `scripts/check_docs.py` と `assets/templates/`**。この文書がそれらと食い違ったら、コードに合わせてこの文書を直す。

## 0. 用語

「解説メモ」という語は、次の 2 つを指す。文書の中では、どちらの意味かを下の表で決めて使い分ける。

| 用語 | 指すもの |
|---|---|
| 解説メモ一式 | 作業フォルダの 5 ファイル（`README.md`・`01_source.md`・`02_explanation_memo.md`・`11_question_and_answer.md`・`12_LLM_prompts_as_guide.md`） |
| 解説メモ | `02_explanation_memo.md` の 1 ファイル（解説の本文） |

## 1. 作業フォルダ

```
<作業フォルダ>/
├── README.md                     必須
├── 01_source.md                  必須（入力 MD の複製。本文は変えない）
├── 02_explanation_memo.md        必須
├── 11_question_and_answer.md     必須
├── 12_LLM_prompts_as_guide.md    必須
└── out/
    ├── 00_manifest.json          必須（検査 C-1）。入力の本文のハッシュなど
    ├── 00_run-report.md          事前確認の答え・採った既定値・判定・検査の結果
    ├── 02_overview.md 〜 11_sample-questions.md   中間生成物（§3）
    └── （05_group-analysis-N.md はグループの数だけ）
```

- **最終ファイルは `out/` を参照しない**（C-3）。`out/` を Git 管理の外に置いても、最終ファイルだけで読める。
- 番号の空き（03〜10、13 以降）は、利用側が足すファイルのために残す。
- `out/09_input-memo.md` は最終ファイルに転記しないが、後工程のために残す。

## 2. 最終ファイルの見出し

`##` の見出しは名前と順序を固定する（C-2）。`README.md`・02・11・12 には、利用者が足した `##` の節があってよい（そのまま残す）。`01_source.md` の冒頭には `## セクション目次` 以外の `##` を置かない。

**共通の決まり**
- 先頭 2 行は `###### [toTopPage](./README.md)` と `###### [toREADME](./README.md)`。どちらも作業フォルダの中の README を指す（C-5 で飛び先を確かめる）。
- 必須の `##` の前に、`-----` と `[toTop](#totoppage)` を 1 行ずつ、見出しの直前に置く。
- ファイルの末尾は `-----` と `[toTop](#totoppage)`（`01_source.md` は入力の複製で終わるので除く）。
- 題名の見出し（`# …`）の下に、`` - `title`: … `` と（あれば）`` - `url`: … `` の箇条書きを置く。5 本で同じ値（C-10）。
- コードブロックの中の `#` は見出しとして数えない（`out/` のファイルでも同じ。記事のコードを `out/05` に引用するとき、コードの中の `## …` の行は見出しとして扱われない。コードブロックは必ず閉じる）。

### 2-1. README.md
| 順 | 見出し・行 | 中身 |
|---|---|---|
| 1 | `# 資料：<題名>` | |
| 2 | 箇条書き `` - `key`: value `` | `title`・`url`（あれば）・`source_format`・`retrieved_at`・`profile`・`content_type`（動画は `channel`・`published`・`duration` も） |
| 3 | `## セクション` | セクション一覧（§2-6）。`01_source.md` の目次と同じ内容。分割なしのときは「分割なし」の 1 行だけ |
| 4 | `## 概要` | 本文の概要（200〜400 字。上限 400 字）。図が再現されていないときの注意 |
| 5 | `## 生成AIの総括` | 総括の題（`###`）・横断分析・一言まとめ |
| 6 | `## 本文` | `01_source.md` へのリンク（C-11） |
| 7 | `## 解説メモ` | `02_explanation_memo.md` へのリンク |
| 8 | `## FAQ` | `11_question_and_answer.md` へのリンク |
| 9 | `## LLM 用プロンプト` | `12_LLM_prompts_as_guide.md` へのリンク |

### 2-2. 01_source.md
入力 MD の**複製**。本文は一字も変えず、冒頭だけを足す。

| 順 | 行 | 中身 |
|---|---|---|
| 1 | `# 本文：<題名>` | |
| 2 | 箇条書き | `title`・`url`（あれば）・`source_format`・`retrieved_at`（動画は `channel`・`published`・`duration` も）・`解説の入口：[README.md](./README.md)` |
| 3 | `> 要約：…` | 200 字以内（C-6・C-11） |
| 4 | `## セクション目次` | セクションに分けられるときだけ（§2-6）。分けられないときは節ごと省く |
| 5 | `<!-- source-body:start -->` | 本文の開始の印。この行の**次の行から最後まで**が複製 |
| 6 | 本文 | 入力 MD の frontmatter を除いた本文 |

- 本文の保存形（`_common.normalize_body`）: 改行を LF にそろえ、末尾の改行を 1 つにそろえる。途中は一字も変えない。ハッシュ（SHA-256）はこの形で取り、`out/00_manifest.json` の `body_sha256` に書く（C-9）。
- 冒頭の `-----`・`[toTop]` は、目次の前と、印の直前に置く。
- 清書・誤変換の訂正は行わない。誤変換らしい箇所は、解説の中で `【推測】` を付けて扱う。

### 2-3. 02_explanation_memo.md
| 順 | 見出し | 中身 |
|---|---|---|
| 1 | `# 解説メモ：<題名>` | |
| 2 | `## 解説` | `### 1. 要約`／`### 2. 例え話`／`### 3. セクション別の解説`／`### 4. ユースケース`／`### 5. 理解を深める質問`（この順・各 1 回）。3 の中は `#### <N>. <セクション名>（<範囲>）`。5 の中は `####` で 5 問（各問の見出しの下に回答） |
| 3 | `## テーマ：<グループ名>`（1 つ以上） | `### 背景`／`### キー概念`／`### 詳細解説`／`### 注意点・限界`／`### ポイントまとめ`／`### 確認の質問`（この順・各 1 回） |
| 4 | `## 活用案` | `### 案1：<視点>`・`### 案2：…`・`### 案3：…`（この順に 3 つ）。各案の末尾に `（N字）` |

`## 解説` が最初、`## 活用案` が最後。`## テーマ：` はその間。グループ名は重複しない。

### 2-4. 11_question_and_answer.md
| 順 | 見出し | 中身 |
|---|---|---|
| 1 | `# FAQ：<題名>` | |
| 2 | `## FAQ｜グループN：<グループ名>`（N は 1 から連番） | `### <通し番号>. <題>`（通し番号は全グループを通して 1 から）。各 FAQ に `- **質問**：`・`- **回答**：`・`- **具体例**：`・`- **該当箇所**：` |

グループ名は、02 の `## テーマ：<グループ名>` と同じ名前・同じ順序（C-10）。

### 2-5. 12_LLM_prompts_as_guide.md
| 順 | 見出し | 中身 |
|---|---|---|
| 1 | `# LLM 用プロンプト：<題名>` | |
| 2 | `## システムプロンプト` | 使い方の 1〜2 行、コードブロック（**ちょうど 1 つ**）に本文、`生成したモデル：<名前>`（1 つだけ。実行したモデル） |
| 3 | `## 活用例：サンプル質問` | `### 初心者向け`／`### 中級者向け`／`### 上級者向け` |

### 2-6. セクション一覧の書式
`README.md` の `## セクション` と `01_source.md` の `## セクション目次` は、同じ項目を同じ書式で書く（C-10）。

```
- <番号> : <名前>[ ｜ <詳細>]
```

- 番号は 1 から連番。名前と詳細の区切りは半角空白・全角の `｜`・半角空白。
- 名前はリンクにしてよい。README では `[名前](./01_source.md#アンカー)`、`01_source.md` では `[名前](#アンカー)`。比べるときはリンクを外した文字で比べる。
- 詳細: 動画は `00:00〜00:40`（スキルが区切ったときは `スキルが区切った・00:00〜00:40・「書き出し 20 字」`）、資料は `p.3〜5` など。見出しがある記事は省いてよい。
- 本文には何も挿入しない。見出しが無い入力のセクションは目次の中だけにあり、本文へは飛べない。

## 3. out/ の中間生成物

ファイル名とステップは次の表のとおり（`03`〜`10` の番号の空きは、利用側が足すファイルのために残す）。

**セクション見出し（`02_overview.md` の `### <N>. <セクション名>（<範囲>）`）の書き方**
- `<セクション名>` は README のセクション名を**そのまま**書く（入力の見出しが `1. 目的と範囲` のように番号を含んでいても、外さない。`### 1. 1. 目的と範囲` のように番号が重なってよい。C-7・C-10 が名前で照合するため）。
- `<範囲>` は括弧ごと**省かず**、次のとおり書く: 動画＝`00:40〜03:15`（スキルが区切ったときも同じ）／ページ・スライドのある資料＝`p.3〜5`・`スライド3`／見出しだけで区切られた記事・資料＝`見出しの節`。

| ファイル | ステップ |
|---|---|
| `02_overview.md` | Step 1 体系的解説 |
| `03_deep-questions.md` | Step 2 質問への回答 |
| `04_grouping.md` | Step 3 グループ分け |
| `05_group-analysis-N.md` | Step 4 グループ別解説 |
| `06_summary.md` | Step 5 総括 |
| `07_reflection.md` | Step 6 活用案 |
| `08_faq.md` | Step 7 FAQ |
| `09_input-memo.md` | Step 8-A 情報収集メモ（転記しない） |
| `10_system-prompt.md` | Step 8-B システムプロンプト |
| `11_sample-questions.md` | Step 9 質問例 |

先頭のメタ情報は次の形にそろえる。

```markdown
# <ファイルの題>

> 資料: <題名>
> ステップ: Step <N> - <ステップ名>
> 生成日: <YYYY-MM-DD>

---
```

### out/00_manifest.json
```json
{
  "schema": 1,
  "skill_version": "0.0.1",
  "created_at": "<ISO8601>",
  "input": {"path": "<入力 MD のパス>", "sha256": "<入力ファイルのバイト列のハッシュ>", "bytes": 1234},
  "body_sha256": "<01_source.md の本文（正規化後）のハッシュ>",
  "profile": "video | article | document",
  "frontmatter": {"title": "…", "source_format": "…"},
  "foreign_sections": [{"file": "README.md", "heading": "<見出し>", "level": 2, "sha256": "<節のハッシュ>"}]
}
```
`foreign_sections` は、既にあるフォルダを渡されたときに、スキルが作っていない節を記録する（C-9 が前後一致を確かめる）。節のハッシュは `_common.section_text` の結果を `normalize_body` にかけたものの SHA-256。

### out/00_run-report.md
入力・事前確認（聞いたことと答え、聞かずに採った既定値）・取り込み（セクションの数と決め方）・省いた確認（グループ分けで採った案と理由）・自己評価（回ごとの検査結果）・確認していないこと。

### 3-1. out/ の各ファイルの書式（生成の決まり。`assemble.py` が機械で転記できる形）

どのファイルも、先頭に上のメタ情報（`# 題` ＋ `> 資料:` `> ステップ:` `> 生成日:` ＋ `---`）を置く。本文はその後ろ。
見出しの名前と順序は**この表のとおり**にする（転記の目印になる）。

| ファイル | 本文の書式 |
|---|---|
| `02_overview.md` | `## 1. 要約`／`## 2. 例え話`（先頭に `【補足】…` の 1 行）／`## 3. セクション別の解説`／`## 4. ユースケース`／`## 5. 理解を深める質問`（番号つきリストで 5 問）／`## 6. 出力品質の検証`（転記しない）。`## 3.` の中は `### <N>. <セクション名>（<範囲>）` ごとに、内容の箇条書きと、`- **根拠**：…「引用」` の行 |
| `03_deep-questions.md` | `### <回答の要点>` が**ちょうど 5 つ**（`02` §5 の質問と同じ順）。各 `###` の下に、`- 回答：…`・`- 解説：…` の箇条書き（**質問は書かない**。質問文は 02 にあり、転記で各問の見出しになる）。`###` は質問の言い換えに留め、**結論（数値・最大／最小・断定）を見出しに詰めない**（見出しの断定が、本文と食い違う誤りの元になる。結論は `- 回答：` に書く）。自己検証の節は付けない |
| `04_grouping.md` | メタ情報（`---` の後ろ）の最初の行に `> 採用: <採った理由>`、続けて `## グループ<N>：<グループ名>`（N は 1 から連番）。各グループの下に `- セクション<番号>：<名前>` の箇条書き（順序は元のまま）。グループ名は重複しない |
| `05_group-analysis-<N>.md` | （`-----`・`[toTop]` の区切りは付けない。転記で付く）`## テーマ：<グループ名>`（`04` のグループ N と同じ名前）の下に `### 背景`／`### キー概念`／`### 詳細解説`／`### 注意点・限界`／`### ポイントまとめ`／`### 確認の質問`（この順・各 1 回） |
| `06_summary.md` | 本文の最初の行が `### <総括タイトル>`。続けて `- 横断分析：`（行末は空）の下に、視点ごとの子箇条書き `  - <視点名>：<1 文>` を **3〜4 個**。（1）（2）…を 1 行に並べない。最後に `- 一言まとめ：…` の 1 行。**`##` は使わない**（README の「## 生成AIの総括」の中にそのまま写る） |
| `07_reflection.md` | `### 案1：<視点>`・`### 案2：<視点>`・`### 案3：<視点>`。各案は 1 つの段落。**字数は書かない**（転記のときにスクリプトが実測で足す） |
| `08_faq.md` | `## グループ<N>：<グループ名>`（`04` と同じ名前・順序）の下に `### <番号>. <題>`（番号は仮でよい。転記で通し番号にそろえる）。各 FAQ に `- **質問**：`・`- **回答**：`・`- **具体例**：`・`- **該当箇所**：` |
| `09_input-memo.md` | 自由（転記しない） |
| `10_system-prompt.md` | メタ情報に `> モデル: <実行したモデルの名前>` を足す（自分が把握している名前を 1 つ、そのまま。例：`Claude Sonnet 5.5`）。本文はシステムプロンプトだけ（コードブロックで囲まない。見出しを使ってよい） |
| `11_sample-questions.md` | `### 初心者向け`・`### 中級者向け`・`### 上級者向け`（この順）。各レベルの下に質問の箇条書き |

`assemble.py` が行う（LLM は手で写さない）。

## 5. 書き方の決まり

### 5-1. 文字数
| 対象 | 上限 | 場所 |
|---|---|---|
| 要約 | 400 字 | 02「### 1. 要約」の本文 |
| ポイントまとめ | 70 字 | 02 の各テーマの `### ポイントまとめ` の本文 |
| 活用案（各案） | 400 字 | `### 案N` の本文（末尾の `（N字）` は数えない） |
| システムプロンプト | 2000 字 | 12 のコードブロックの中身 |
| README の概要 | 400 字 | README「## 概要」の本文 |
| 01_source.md の要約 | 200 字 | `> 要約：` の後ろ |

**数え方**（`_common.char_count`。`len()` のコードポイント数）
- 通常（要約・ポイントまとめ・活用案・概要）: 改行を LF にそろえ、Markdown の記号（行頭の `#`・`>`・`- `・`* `・`+ `・`1. `、リンクと画像の記法（文字だけ残す）、`*`・`_`・`` ` ``・`~`・`|`）と、すべての空白（全角空白を含む）を除いて数える。
- システムプロンプト: コードブロックの中身から、空白だけを除いて数える。

上限を超えたら**文章を直す**（上限や数え方を変えない）。`wc -m` はバイト数を返すことがあるので使わない。

### 5-2. 根拠と補足
| 種類 | 書き方 |
|---|---|
| 本文に書いてあること | 根拠を示す。`video`：`セクション2 在庫回転率とは [03:15]「…」`／`article`：`「<見出し>」の節「…」`／`document`：`第2章 p.5「…」`・`スライド3「…」`。ページ・スライド番号が無い資料は `「<見出し>」の節「…」`（article と同じ）。補足の節（pptx の末尾「補足」など）は `補足の節「…」` |
| 引用（「…」） | **本文と一字一句同じ**。途中を略すときは `…（中略）…` で 2 つに分ける。**引用の中に「」を含めない**（本文に入れ子の「」があるときは、入れ子を含まない部分だけを切り出すか、`…（中略）…` で分ける。C-8 が「…」を取り出すため） |
| 図の数値（SVG・表） | 再現されている図・表は根拠に使ってよい。SVG は、テキストの文字をそのまま引用する（`図1「4月 100」`）。表は、セルの文字を引用する |
| 例え話・一般知識・筆者（AI）の整理 | 段落・箇条の頭に `【補足】`。節の全体が補足のとき（「### 2. 例え話」）は見出しの直後に 1 回 |
| 推測 | `【推測】`。断定しない |
| 本文から分からないこと | 「本文には書かれていない」と書く。埋めない |

根拠の行は、行の中に `根拠：`・`該当箇所：`（太字の `**根拠**：`・`**該当箇所**：` でもよい）を含める。C-8 は、**この行の中の「…」だけ**を照合する。根拠でない行の「…」（用語の引用、`03` の解説での言及など）は照合しない。本文を引用して示したいときは、根拠の行にする。

### 5-3. そのほか
- 用語は本文の表現に合わせる。コードは本文のまま引用する。
- プレースホルダ（`{{…}}`・`＜…＞`・`TODO`）を残さない。
- 相対リンクは `./` から書き、作業フォルダの中だけを指す。

## 6. 検査項目（`check_docs.py`）

### 6-1. 出力の形（標準出力）
```
check_docs: <作業フォルダ>
PASS  C-1  必須ファイル
FAIL  C-8  引用の照合
       02_explanation_memo.md:75  引用が 01_source.md の本文に無い: 「…」
結果: 10 PASS / 1 FAIL
```

`--json`:
```json
{"schema": 1, "folder": "<絶対パス>", "passed": false, "summary": {"pass": 10, "fail": 1},
 "items": [{"id": "C-1", "name": "必須ファイル", "status": "PASS", "findings": []},
           {"id": "C-8", "name": "引用の照合", "status": "FAIL",
            "findings": [{"file": "02_explanation_memo.md", "line": 75, "message": "…"}]}]}
```
`file`・`line` は無ければ `null`。終了コードは 0（全項目 PASS）／1（不合格あり。`REASON=CHECK_FAILED`。作業フォルダが無いときは `REASON=NO_INPUT`）／2（引数の誤り）。

## 7. ひな形のプレースホルダ（`assets/templates/`）

ひな形は `{{名前}}` を置き換えて使う（`scaffold.py`・`assemble.py`）。最終ファイルに `{{` が残ってはいけない（C-4）。

| ひな形 | プレースホルダ |
|---|---|
| `README.md` | `title`・`meta_bullets`・`sections`・`overview`・`summary_block` |
| `01_source.md` | `title`・`meta_bullets`・`summary`・`toc_block`（目次があるとき `-----`・`[toTop]`・`## セクション目次`・一覧・空行。無ければ空）・`body` |
| `02_explanation_memo.md` | `title`・`meta_bullets`・`overview_block`・`theme_blocks`（各テーマが区切りから始まる）・`reflection_block` |
| `11_question_and_answer.md` | `title`・`meta_bullets`・`faq_blocks`（各グループが区切りから始まる） |
| `12_LLM_prompts_as_guide.md` | `title`・`meta_bullets`・`system_prompt_intro`・`system_prompt`・`model`・`sample_questions` |

`meta_bullets` は `` - `key`: value `` の行の並び（値が無い項目は行ごと出さない）。

## 8. 完了報告の形

```
解説メモ一式を作りました。
- 作業フォルダ: <パス>
- 入力: <入力のパス>（プロファイル: <video|article|document>／内容の種類: <…>）
- 作ったファイル: README.md・01_source.md・02_explanation_memo.md・11_question_and_answer.md・12_LLM_prompts_as_guide.md
- 検査: C-1〜C-12 合格（<n> 回目）／読み合わせ R-1〜R-4 合格
- 採った既定値: <聞かずに決めたこと>
- 確認していないこと: <あれば>
- 残った項目: <あれば。なければ「なし」>
- 次にできること: スライドにする（指示文の例）
```
不合格が残ったときは、1 行目を「解説メモ一式を作りましたが、検査に通っていない項目があります。」にして、項目と場所を並べる。
