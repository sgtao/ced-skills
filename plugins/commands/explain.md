# /ced-skills:explain — 解説メモと解説スライドを作る

入力: $ARGUMENTS

## 手順

### 1. 引数を読み、足りないものだけを聞く
引数は次のとおり。入力（URL かファイルのパス）は必須。
- `--out <出力フォルダ>`（既定の代わりに聞く項目）
- `--slides <枚数>`（スライドの枚数）
- `--audience <読み手>`（読み手の想定）

判定と動き（この順で）:
1. 入力が無いときは、AskUserQuestion を使わず、入力を 1 行で尋ねて止まる。
2. `--out`・`--slides`・`--audience` の 3 つがすべて引数にあるときは、**AskUserQuestion を呼ばない（0 回）**。そのまま手順 2 へ進む。
3. 1 つでも足りないときは、**足りないものだけを、AskUserQuestion の 1 回の呼び出しにまとめる**。質問は最大 3 問で、4 問を超えない。
   - 質問文・選択肢・説明はすべて日本語で書く。コマンド名やオプション名は原文のままでよい。
   - 質問は、下の「質問の定義」のとおり。
4. 答えを受け取ったら、二度と質問しない。答えの無いものは既定値で進める（出力先は `./explain-out/<入力の名前>`、枚数は 6、読み手は「初めて読む人」）。

#### 質問の定義
- Q1 出力先（`--out` が無いとき）: 「出力先はどこにしますか？」。選択肢: `./explain-out/<入力の名前>（既定）`／別のフォルダ（「その他」に自由に入力してもらう。ここで再び聞き直さない）
- Q2 枚数（`--slides` が無いとき）: 「スライドは何枚にしますか？」。選択肢: 6 枚（既定）／10 枚／15 枚
- Q3 読み手（`--audience` が無いとき）: 「読み手はどなたですか？」。選択肢: 初めて読む人（既定）／実務で使う人／専門家

#### 入力の名前と出力の形
`<入力の名前>` は、ファイルは拡張子を除いた名前、YouTube は動画 ID、URL はホストとパスの英数字をつなげた名前（使えない文字は `_`、80 字まで）。

出力は、次の形に**固定**する（実行ごとに形を変えない。別名のフォルダや入れ子を作らない）。

```
<出力先>/
├── explained/                 解説メモ（README.md・01_source.md・02_explanation_memo.md・
│   │                          11_question_and_answer.md・12_LLM_prompts_as_guide.md）
│   └── out/                   解説メモの作業ファイル
├── <入力の名前>-slides.md     解説スライド（編集用）
├── <入力の名前>-slides.html   解説スライド（ブラウザで開く）
└── .work/                     変換した Markdown などの中間ファイル
```

- 解説メモのフォルダの名前は必ず `explained`（`<ID>_explained` にしない）。スライドをその中に入れない。
- 変換した Markdown や状態などの中間ファイルは、出力先の直下ではなく `.work/` に置く。
- `<出力先>` の中に、さらに `explain-out/` や `<名前>/` を作らない。

### 2. 入力を Markdown にする
- `ced-url-to-md` のスキルを使い、入力を Markdown に変換する（YouTube は字幕、PDF は `ced-pdf-to-md-ja` に委譲される）。
- 変換した Markdown は `<出力先>/.work/md/<入力の名前>.md` に置く（出力先の直下に置かない）。
- 変換できないときは、理由を報告して終わる。

### 3. 解説メモを作る
- `ced-craft-explanation-docs` のスキルを使い、手順 2 の Markdown を 1 つ渡して解説メモ一式を作る。
- 子スキルの質問を止めるため、**「質問なしで」と明示して**、次の値を渡す（子スキルの Step 0 の項目に当たる）。
  - 作業フォルダの場所: `<出力先>/explained`（この名前のまま。`<ID>_explained` にしない）
  - 読み手と目的: 手順 1 で決めた読み手（`--audience` の値）。**読み手は、内容の向き（誰に向けて書くか）として渡す。話題として扱わない**（読み手の名前を解説の題材にしない）
  - 本文に無い補足: 足す。必ず印を付ける。Web 検索はしない
  - 内容の種類とグループ分け: 子スキルに任せる（聞かない）
- 同名のフォルダの確認（子スキルの Q6）だけは、聞く必要がある場合に限り子スキルが尋ねる。

### 4. 解説スライドを作る
- `ced-websearch-slide-ja` のスキルを使い、解説メモをもとにスライド MD を書く。
- スライドの質問と確認をすべて止めるため、**「質問なしで」と明示して、確定値を渡す**（子スキルの「確定値モード」）。
  - 目的: おまかせ
  - 情報ソース: 解説メモだけ（Web 検索しない）
  - ビジュアル: グラフ作成＋画像なし
  - 枚数: 手順 1 で決めた枚数（`--slides` の値）
  - 保存先: `<出力先>`（ファイル名は `<入力の名前>-slides.md`・`<入力の名前>-slides.html`。テーマの部分を `<入力の名前>` にする）
  - 想定読者: 手順 1 で決めた読み手（`--audience` の値）
- スライド MD を `mdss-convert --json-only` にかけ、`lint` 配列の error と warn を直す。
  直したあとの error と warn が 0 になるまで繰り返す（同じ方法で 2 回直せなかったら、残りを報告する）。
- lint が通ったスライド MD から HTML を作る。`.md` と `.html` を、`<出力先>` の直下に置く。

### 5. 報告する
- 作ったファイルのパス、lint の結果（error／warn の数）、未検証のこと（画像の確認など）を 5 行以内で書く。
- 次の一手として 1 行だけ提案してよい（依頼にない機能は足さない）。
